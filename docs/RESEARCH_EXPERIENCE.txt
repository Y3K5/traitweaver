TRAITWEAVER — THE RESEARCH IDEA FIRST
October 31, 2026. Local human-facing experience, not a new live-model run.

THE IDEA
A researcher brings a desired change or a question. Traitweaver connects the
available evidence, the biological/input identity, a useful local check and the
next study requirements. The main view should help someone understand what to
do next. Exact IDs, saved inputs/outputs and limitations stay inspectable.

CURRENT FOUR STARTER STUDIES
Algae & phosphorus: public growth/uptake observations, qualified reference
identity and proposed measurement modules. Distinguish removal, assimilation,
collection and plant use. Growth acceptance margin and recovery outcomes remain
unknown. No biological winner or engineered-organism result.
Understand GFP: qualified public identity, database annotations and three model
predictions. Missing structure/version/assay evidence is still missing.
Plan an RNA study: deliberately incomplete synthetic design/sample/input records.
Check duplicates, layout conflicts, comparison, independent units, reference
versions and QC. Zero supplied FASTQ files is not an unknown read count. No DE.
Make it repeatable: synthetic environment/input/run records. Produce a concrete
repair checklist. Exit zero alone is not a reproduced or verified result.

THE EXPERIENCE
Choose a study card. Follow What we know -> Follow the biology (or Know your
inputs) -> Check what’s missing -> Choose the next step -> Shape the study ->
Save for review. Your notes and earlier versions are under an expandable panel.
Why this step? explains the purpose in ordinary language. Show evidence opens
source records locally. Raw IDs and JSON are under the saved-record disclosure.
The palette, underlying scientific data/mapping/tools and export privacy gate
are preserved. Concept graphics are labelled illustrations, not structures,
experiments or simulations. Reduced-motion preference disables animation.

WHAT MUSE ACTUALLY DOES
The original public algae workflow had one accepted real Meta cycle: one check
selection, a local endpoint-coverage result, then a separate Muse reassessment.
Its saved local receipts record muse-spark-1.3, two accepted requests, 5,939 input
and 1,413 output tokens and estimated USD 0.013429. Billing/provider identity are
not independently authenticated. Outcome: unavailable evidence for the target;
next step: researcher review of missing measurements. This was useful abstention,
not a successful phosphorus-recovery experiment.

When an owner-supplied real completed-cycle packet is loaded, the algae workbench
shows How Muse helped, the saved AI -> tool -> AI sequence and its usage link.
When --demo is loaded, it explicitly says Synthetic replay loaded. Other study
cards always say their first real Muse review is pending. The saved algae cycle
must never stand in for a real protein, RNA, reproducibility or new action-card
review. The current action cards are authored proposals or labelled synthetic/
imported priorities, not newly generated free-form research discoveries.

Review public inputs for Muse prepares the existing strict assistant request
for the selected fixed case. It excludes all workbench notes, even a private
synthetic test canary. No source retrieval, transport, credential read or spend
is enabled. Origin/session and current-study/workbench identity are required.
Prepared previews are invalidated when the saved view changes. A new live batch
needs exact-payload, destination, token, request-count and spending review plus
an explicitly approved runner. Past approvals/available credits do not cover it.

WORKFLOW EXERCISE

uses four existing cases and six navigation orders per case: 24 offline software
journeys, with actual local checks, synthetic priorities, immutable note history,
JSON/Markdown and read-only reopen. Sockets are prohibited; 0 live provider calls
and 0 experiments. The output includes four exact unsent Muse request previews.
Do not mistake these for 24 distinct scientific studies or AI reliability proof.
Generated outputs stay outside the publishing tree. Do not publish automatically.

WHAT COMES NEXT FOR MORE TRAITS
1. Review the four exact public/synthetic payloads and the first real-model test
   scope. Confirm current pricing and an explicit cap; no batch is currently
   executable/authorized. Use no retries or provider fallback.
2. Qualify each new trait study's public source bundle: organism/strain, endpoint,
   measurement basis/units, controls, conditions, uncertainty and source locators.
   Separate observations, annotation, predictions and proposals. Unknown candidate
   requirements, interactions and species transfer cannot become model facts.
3. Add a separately reviewed/versioned case or program contract rather than
   silently widening the closed four-case assistant. Verify useful next actions,
   contradictions, missing metadata, zero/null and export fidelity for each case.
4. A scientist qualifies comparisons, readouts, independent units and approved
   procedures before experiments. No cassette/guide/culture/inoculation protocol,
   detailed organism engineering or new wet-lab execution is supplied here.

LIMITS

actual local readiness checks, saved real algae contribution, request preview,

qualification and timing limits remain separate. Notes remain in server memory

prose; owner review remains required. No new provider call, install or Git write.
