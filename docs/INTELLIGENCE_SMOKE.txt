NOVEMBER 3, 2026 UTC — SINGLE META INTELLIGENCE SMOKE TEST

Status: adapter implemented and tested offline; no live run authorized or claimed.
tools/muse_intelligence_smoke.py is a separate CLI adapter. Existing v1/v2/v3
request bytes, scientific inputs, old transport runners and browser stay unchanged.
It prepares exactly one fixed v2 continuation request. The v2 case has two eligible
checks after a synthetic selection/reassessment and an actual local evidence audit.
The current v3 fixture leaves one eligible check; that would not demonstrate a
prioritization choice. This smoke test does not evaluate useful model adaptation.

PAYLOAD AND PROVIDER
POST https://api.meta.ai/v1/responses
Model: muse-spark-1.3, Standard mode; store=false; max_output_tokens=1024.
No tools, search, files, alternate endpoint, retry, fallback or automatic local
execution. All wire bytes come from the unchanged v2 contract: admitted public
source/candidate/context records, a synthetic prior decision and reassessment,
the actual source-bound software audit, unresolved requirements and eligible
combination/transfer checks. It contains no owner notes or private study data.
The reference CC-503 and study UVM4 qualifications remain distinct.

Official public references checked November 3, 2026:
https://dev.meta.ai/docs/models
https://dev.meta.ai/docs/pricing-rate-limits
Muse Spark Standard: input USD1.25 / million tokens; output USD4.25 / million;
cached input USD0.15 / million, discount not assumed. No search/tool surcharge
is included because no tool is offered. API account/model access, credits,
payment method, taxes, team limits and actual billing have not been checked.

Proposed ceiling: USD0.10 for one attempted request. The packet includes two
estimates using the full UTF-8 wire size: planning input bytes/4; conservative
input allowance bytes+1024. Both add all 1024 permitted output tokens. These are
application estimates, not a tokenizer proof or provider/account billing cap.
No token-counting or billing API is called. Usage above the allowance is reported
and rejected after the attempt; the adapter cannot undo provider charges.
The unchanged 1024-token limit may produce an incomplete answer. Stop and review
that outcome; a bigger request would need a separately versioned contract and
fresh payload/budget approval. Never silently trim usage to fit an old receipt.

OFFLINE PREPARATION
From the actual isolated cloud checkout, choose a fresh external directory:
  python3 -B tools/muse_intelligence_smoke.py prepare /tmp/traitweaver-muse-smoke
  python3 -B tools/muse_intelligence_smoke.py verify /tmp/traitweaver-muse-smoke
REQUEST.json contains the exact outgoing HTTP body, without a trailing newline.
SOURCE.json and REQUEST_RECORD.json preserve the local source/request history.
PLAN.json binds location, code/data hashes, payload, pricing, expiry and ceiling.
REVIEW.txt describes the proposal. UNSIGNED_APPROVAL.json has approved=false.
Preparation does not create OWNER_APPROVAL.json or read a credential. The fixed
fixture timestamp labels synthetic history; it is not an actual run timestamp.

SEPARATE EXECUTION GATE
Only after explicit owner approval of the exact PLAN approval hash, outgoing
payload, provider, output limit and budget may the reviewed unsigned draft be
copied to OWNER_APPROVAL.json with approved=true. This tool provides no automatic
grant command. OFFLINE_APPROVAL.json is test-only and cannot authorize a live run.
The runtime also requires the explicit flag and the exact reviewed approval hash:
  python3 -B tools/muse_intelligence_smoke.py run /tmp/traitweaver-muse-smoke \
    --allow-live --approval-sha256 <reviewed PLAN approval_sha256>
Do not execute this command as part of preparation or testing. Real stdin/stderr
terminals are required before a MODEL_API_KEY lookup or hidden key prompt.
Never put credentials in command arguments, packets, screenshots or chat.

The cloud configuration inspected during development blocks api.meta.ai and
has no credential bindings. No network policy or credential configuration was
changed. Authorized network access and account setup remain execution blockers;
an existing key or network permission would not grant payload/spending approval.
The transport rejects redirects and does not inherit machine proxy routing.
Its 60-second timeout applies to socket operations, not a guaranteed total wall
time or provider cancellation. An interrupted request can still incur charges.

At execution, code/data/request/location/approval/expiry pins are rechecked after
any key prompt and again at the lowest send entry. Reviews expire after 24 hours;
the public-price review also expires after seven days. Durable exclusive attempt
and POST markers forbid retries and duplicate sends from the same packet. A
STOP.requested file blocks a request before dispatch; it cannot cancel a sent one.
Recreating another packet never inherits approval. This is a local application
guard, not protection against an operator intentionally modifying trusted code.

OUTPUTS AND PROVENANCE
No raw response, reasoning, provider ID, cookie, key or arbitrary error message
is saved. RECEIPT.json records the request/response hashes, transport attempt,
numeric usage, estimated cost and unresolved reservation. Partial, missing or
invalid usage remains unknown, not zero. Rejected/incomplete answers retain
known counts and stop. Usage estimates are not independent billing confirmation.
The live_transport_calls field counts marked attempted POSTs, not provider receipt
or completion. Offline fake transports always report zero live calls and explicit
synthetic provenance. Test-only fake grants/artifacts are temporary fixtures.

On structural success, PROPOSAL_REVIEW.json is an unchanged v2 review package:
it reopens read-only and cannot dispatch a check. Its existing parser reports
owner_imported_authenticity_unverified and transport_calls=0; that describes the
transport-free parser, not the separately recorded CLI attempt. RECEIPT.json alone
records locally observed direct Meta transport. Neither is independent provider
authentication. Synthetic ancestors remain synthetic; no labels propagate to
the phosphorus showcase or v3 histories. Source references do not prove entailment,
scientific validity or useful prioritization. Any later check requires its own
existing explicit human approval and execution workflow.

Verification and reopening only validate retained receipts; they never dispatch
a local check. Preparation deliberately computes one fixed local evidence audit.
Generated packets, approvals, receipts and logs stay outside the public candidate.
