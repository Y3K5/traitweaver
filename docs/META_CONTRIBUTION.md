# What Meta contributed

This explanation distinguishes recorded model work, local software and replay.
It introduces no new model calls, spending approval or claims of scientific success.

## Documented real algae cycle: October 29, 2026

`LIVE_RUN_SUMMARY.txt` records an owner-approved run using `muse-spark-1.3`
(Muse Spark, Standard mode), sent to Meta Model API's `/v1/responses` endpoint.
The recorded sequence is:

1. Muse selected the registered `endpoint_coverage` check from the supplied,
   source-bound choices.
2. Local deterministic software performed that check. It found no quantified
   recovered-product phosphorus endpoint in either admitted path, differing source
   contexts and an unknown growth margin. These are evidence gaps, not proof that
   either biological approach fails.
3. Muse reviewed that local result and returned an unavailable assessment with a
   researcher-review next step for the proposed measurement plan.
4. The saved history retains initialization, decision acceptance, local result
   and reassessment acceptance as four revisions.

This is a bounded model decision -> local check -> model reassessment contribution,
not just a model name on the UI. Application code and validation are documented as
Codex-authored; the model did not generate the application or execute a laboratory
experiment. New action/measurement cards are authored proposals unless their own
accepted record explicitly establishes a separate model contribution.

The original response schema is deliberately narrow. Selection chooses a
registered check, rationale code and citations; the application supplies the
explanatory prose, deferred options and conditional branches. Reassessment is
constrained to the locally determined outcome and permitted researcher-review
action for that result. The application also authors the measurement plan.
Displaying those records makes this bounded contribution inspectable; it does
not establish open-ended adaptation or independent plan generation by Muse.

The current Research journey exposes these distinctions in its selected scenes:
actual accepted citations and model fields, saved local result rows, and authored
planning content. Complete linked receipts are required for the model-proof view.
Unknown, partial or inconsistent provenance cannot acquire a saved-real label.

The separate intelligence continuation preview carries prior accepted decisions,
saved results and unresolved requirements for human review. Its options and repeat
rules are deterministic application logic. They are not new Muse output, and the
unchanged v1 model payload does not contain that preview. Preventing redundant
local checks is software behavior, not evidence of model adaptation.

A separate v2 request now includes that reviewed history for a proposed next
selection: prior decisions, exact saved results, reassessments and unresolved
requirements. Its closed schema excludes already checked/failed inputs and adds
explicit result/requirement references. Development used synthetic fixtures only;
the v2 request was not sent to Meta. Local validation yields a proposal review,
not an accepted cycle or executed check. Imported replies remain unverified.
Correct references or a forced single eligible choice do not establish model
understanding, adaptive planning or independent scientific usefulness.

The source summary reports 5,939 input and 1,413 output tokens, including 1,315

replay. Synthetic responses, usage and approvals are software fixtures, not the
real October 29 packet. The replay must never be narrated as a live or recorded
real model response. Browser playback sends nothing and performs no new inference.

`--completed-cycle-dir` / `--completed-cycle-file` viewer. The viewer validates
local links/hashes; those checks do not independently authenticate Meta. Raw
responses, keys, provider identifiers, owner grants and private packets stay out
of this repository. A video may show selected reviewed UI records with accurate
labels; no new paid request or raw-packet publication is required by this plan.
